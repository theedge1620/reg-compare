How to build the dataset
  1. Put the .docx amendment documents to compare in one folder.
  2. Run the analyzer (it sits next to this page): 
    python folder_compare.py "C:\path\to\folder"
    Add --recursive to include subfolders, or -o to choose where the results go.
  3. It writes rulecheck-folder.json (load it here), rulecheck-folder.csv, and — when openpyxl is installed — rulecheck-folder.xlsx with real strikethrough redlines.

Current rule text fetched from the eCFR versioner API v1 via /api/versioner/v1/full/{date}/title-10.xml?part={P}&section={P.S} — date from /api/versioner/v1/titles.json up_to_date_as_of. Only paragraphs referenced in the proposed rule are shown; * * * * * spans collapse unchanged text.
Subsections are matched only within the same section — § 50.55a (b)(2) is compared against (b)(2) of § 50.55a alone, never across sections. A * * * marker means the text up to the next listed subsection is unchanged, so it is not compared. A numbered 46.-style instruction precedes the section it names: where amendatory text follows the section heading, that text is compared and the instruction is shown as context; where the instruction stands alone, the instruction itself is compared, against other instructions only. A number without a § (e.g. 2.326 Motions to reopen.) starts a section only if an instruction names it, or it is a Title 10 section in the eCFR whose heading matches — so quantities such as 0.001 rem are read as text. In definitions sections each “Term means …” is compared only with the same term's definition. Part, subpart and appendix headings, authority citations, footnotes, and any preamble or signature block are not regulation text and are left out. Differences only in punctuation, spacing, case, hyphenation or footnote markers don't count as changes; the redline itself is verbatim. Pick eCFR in the redline picker (or Compare with current eCFR) to redline a draft against the same subsection of the current eCFR, fetched from the eCFR API when you ask; a draft that gives only an instruction has its “remove … and add …” edits applied to the eCFR text. Files are read entirely in your browser — nothing is uploaded; only section numbers are sent to the eCFR.
folder_compare.py applies the same parsing, section-scoped matching and redline logic as Document Comparison to every .docx in a folder. A subsection is listed when two or more documents carry it with differing text; documents that share identical text are grouped into one variant, and each pair of variants is redlined. Text-vs-instruction differences are shown side by side, never redlined. Pick eCFR in the redline picker (or Compare with current eCFR) to redline a draft against the same subsection of the current eCFR, fetched from the eCFR API when you ask; a draft that gives only an instruction has its “remove … and add …” edits applied to the eCFR text. The dataset is read entirely in your browser — nothing is uploaded; only section numbers are sent to the eCFR.
The list of sections with information collection requirements is compiled by build_icr_library.py from each part's “Information collection requirements: OMB approval” section (§ 50.8, § 30.8, …), which names the sections whose collections OMB has approved, plus the forms approved under their own control numbers. A section of the working document is checked when it is on that list; each of its subsections is redlined against the same subsection of the existing regulation in the library, matched exactly as on Document Comparison. Appendices are listed but not compared. The document is read entirely in your browser — nothing is uploaded.
